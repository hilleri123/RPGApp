## Формат описания дефекта

Каждый дефект оформлен единообразно:

- **ID** — стабильный идентификатор (`BE-01`), на него ссылается план исправлений.
- **Severity** — critical / high / medium / low.
- **Где** — файл со ссылкой и номерами строк.
- **Проблема** — что именно не так.
- **Решение** — предлагаемое исправление.

Severity расшифровывается так:

- **critical** — утечка или порча чужих данных, падение эндпоинта, обход аутентификации.
- **high** — нарушение прав доступа, потеря пользовательских действий, некорректное состояние рантайма.
- **medium** — деградация под нагрузкой, скрытые ошибки, расхождение конфигов.
- **low** — качество кода, мусор, вводящие в заблуждение комментарии.

## Отношение к LaTeX-книгам

В `docs/src/**` лежат две книги в LaTeX. Они про то, **как пользоваться сайтом** и как он устроен; эти Markdown-файлы их не заменяют.

| Книга | Исходник | Результат | Публикуется |
|-------|----------|-----------|-------------|
| Руководство пользователя | `src/user-guide.tex` | `out/user-guide.pdf` | Да — раздел «Контакты» на сайте |
| Техническая документация | `src/tech-guide.tex` | `out/tech-guide.pdf` | Нет, внутренний документ |

### Сборка

```
./docs/build.sh              # обе книги + копия PDF в public/ фронтенда
./docs/build.sh user         # только руководство пользователя
./docs/build.sh --no-publish # не трогать public/
```

Нужен TeX Live с кириллицей: `sudo apt install texlive-xetex texlive-lang-cyrillic fonts-dejavu`.

Скрипт кладёт готовое руководство в `RPGWebMainClient/public/rpg-master-user-guide.pdf` — оттуда его отдаёт статикой страница `/contacts`. **PDF нужно коммитить**: сборка фронтенда его не пересобирает.

### Скриншоты

Лежат в `src/assets/screenshots/`. Снимки авторизованных экранов (`user/lobby.png`, `user/session-player.png`, `user/session-master.png`, `user/scenarios.png`, `user/scenario-detail.png`, `user/access-groups.png`) пока не сделаны — нужен доступ к стенду.
